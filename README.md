# Вектор 3.0 — GitHub Pages + Telegram CloudStorage

Эта версия работает **без отдельного API-сервера, SQLite, платного backend и токена бота в исходниках**.

```text
GitHub repository → GitHub Pages (HTML / CSS / JavaScript)
                              ↓ запуск из кнопки бота
                       Telegram Mini App
                              ↓
                Telegram.CloudStorage пользователя
```

GitHub хранит код и размещает страницу. Личные цели в GitHub не отправляются: они хранятся в облаке Telegram отдельно для каждого пользователя и бота. Telegram SDK использует свой API CloudStorage, но создавать собственный сервер для этого не нужно.

## Разместить на GitHub

1. Создайте репозиторий, например `vector-mini-app`, с основной веткой **main**. На бесплатном GitHub Pages обычно нужен публичный репозиторий. Код не содержит секретов и пользовательских целей.
2. Загрузите **содержимое этой папки**, а не саму папку целиком, в корень репозитория. В корне должны быть `package.json`, `dist/`, `tests/` и `.github/workflows/pages.yml`. Убедитесь, что скрытая папка `.github` тоже загружена.
3. Откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
4. В **Actions** выберите `Test and publish Telegram Mini App` и нажмите **Run workflow**, если публикация не началась сама. При каждой следующей отправке в main тесты и публикация выполняются автоматически.
5. Получите URL вида `https://ВАШ-ЛОГИН.github.io/vector-mini-app/`. Все пути к ресурсам относительные, приложение поддерживает подпапку репозитория.

### Альтернатива без GitHub Actions

Если загрузка workflow через веб-интерфейс или разрешения аккаунта мешают: скопируйте файлы **из `dist/` в корень отдельного репозитория**, добавьте пустой файл `.nojekyll`, затем выберите **Settings → Pages → Deploy from a branch → main → /(root)**. Для этой альтернативы серверные файлы и npm не нужны; тесты перед загрузкой запускайте локально.

## Подключить в Telegram

1. Откройте **@BotFather**, создайте бота через `/newbot` или выберите существующего через `/mybots`.
2. Выберите бота → **Bot Settings → Configure Mini App**, включите Mini App и задайте полученный HTTPS URL GitHub Pages. Названия пунктов BotFather могут отличаться в разных версиях.
3. В **Menu Button** задайте тот же URL и подпись, например «Мои цели».
4. Откройте бота и запустите приложение его кнопкой. Используйте современную версию Telegram (CloudStorage API 6.9+ и WebView с CompressionStream).
5. Вверху и в настройках появится **«Облако Telegram»**. Создайте тестовую цель, закройте Mini App и откройте её снова, затем откройте того же бота с другого устройства того же аккаунта.

Токен бота в GitHub, JavaScript или GitHub Actions **добавлять не нужно**. Для кнопки Mini App не требуется постоянно работающий процесс бота. Автоматические ответы на сообщения `/start` и фоновые напоминания этой статической версией не обслуживаются.

## Что сохранено из приложения

Создание и редактирование своих целей, название и описание, категории, дата и время начала, дедлайн, длительность таймера, живые часы (дни / часы / минуты / секунды), обратные отсчёты, дни до дедлайна, действия и их выполнение, прогресс, завершение и повторное открытие целей, поиск, фильтры, статистика и история. JSON-экспорт/импорт и отдельный режим примера. Русский адаптивный тёмный интерфейс, Telegram BackButton и safe areas.

## Как устроено сохранение

Telegram допускает 1024 ключа на пользователя бота, до 4096 символов в значении. Поэтому приложение сжимает JSON в gzip, кодирует его в base64 и делит на фрагменты по 3800 символов. Один снимок ограничен 300 фрагментами; общий JSON ограничен 2,9 МБ, а также действуют пределы 300 целей, 200 действий на цель и 5000 событий. Особенно плохо сжимающиеся данные могут достичь лимита фрагментов раньше; приложение сообщает об этом и не заменяет прежнюю копию.

Сначала записываются фрагменты новой версии с уникальными именами. После подтверждения всех записей обновляется единственный указатель `vx2_head`. SHA-256 выявляет неполную или повреждённую копию. Сохраняется одна предыдущая полная версия; при повреждении текущей приложение пробует предыдущую и показывает сообщение. Ошибки загрузки не превращаются в пустое облако и не перезаписывают данные автоматически.

На время записи интерфейс блокирует новые изменения. Если Telegram не подтвердил запись до истечения ожидания, приложение просит открыть Mini App заново и блокирует дальнейшие записи этой сессии: неизвестно, выполнилась ли операция. После подтверждённых ошибок незавершённые фрагменты удаляются по возможности. При аварийном закрытии часть временных ключей может остаться; их автоматическая массовая очистка не выполняется, чтобы не удалить запись другого активного устройства. Лимит свободного места проверяется перед сохранением.

### Несколько устройств

При открытии приложения и возвращении в него загружается облачная версия. Перед записью проверяется исходная версия и повторно — непосредственно перед переключением указателя. Если обнаружены чужие изменения, приложение загружает их и просит повторить действие.

**CloudStorage не предоставляет транзакции или compare-and-set. Полную защиту от двух строго одновременных записей гарантировать нельзя: последняя запись указателя может стать основной.** Используйте приложение на одном устройстве за раз. Для строгой одновременной совместной работы понадобится серверное хранилище; для личного трекера такая схема обходится без сервера.

### Обычный браузер

При открытии URL вне Telegram используется отдельный localStorage браузера. Он не синхронизируется с Telegram автоматически. Чтобы перенести цели из предыдущей версии, экспортируйте JSON там, откройте новую версию **внутри Telegram**, затем импортируйте копию в настройках (текущие облачные данные будут заменены после подтверждения). Внутри Telegram приложение не переключается молча на локальное сохранение при сбое облака.

## Время

UTC Unix milliseconds, местное отображение. Интервал только обновляет экран: прошедшее время каждый раз вычисляется из абсолютного времени начала, поэтому закрытие приложения не останавливает отсчёт. Дедлайн и таймер длительности независимы. Длительность дня — 24 часа; дни до дедлайна округляются вверх. Завершение фиксирует elapsed по completedAt. Точность зависит от системных часов устройства: CloudStorage не предоставляет серверные часы. Push-уведомлений при закрытом приложении нет.

## Проверка и локальный просмотр

Node.js 22+, устанавливать зависимости не требуется:

```sh
npm test
npm start
```

Открыть http://localhost:4173. `preview.mjs` — только инструмент локального просмотра; для GitHub Pages он не запускается.

27 автоматических тестов проверяют расчёты времени, валидацию данных, облачный roundtrip, большие данные и кириллицу, прерванную запись, конфликт версий, восстановление предыдущей копии, лимит ключей и неопределённый результат записи. CloudStorage в этих тестах заменён моделью callback API: реальная проверка на Android/iOS и втором устройстве выполняется после подключения URL к вашему боту.

Переключение типа в редакторе сохраняет шаги и имеющиеся отметки. Старые записи без kind считаются обычными целями; номер схемы и имена облачных ключей сохранены. Дополнительного импорта данных не требуется.

Главный экран компактнее на телефоне. Проценты подписаны по смыслу. Одинаковые обратные отсчёты объединены; главный счётчик прошедшего времени у целей сохранён. Новая версия загружается по прежнему URL после успешной публикации GitHub Pages.
